## Research-informed UX basis

The [official Devpost page](https://hack-for-humanity-summer-26.devpost.com/) confirms that Innovation/Novelty and UI/UX/Accessibility apply to all entries and that the concussion track also evaluates domain effectiveness, responsible safety, neuroscience/research foundation, technical complexity, and UX/accessibility. The [2026 gallery](https://hack-for-humanity-summer-26.devpost.com/project-gallery) remained unpublished on 2026-08-26, so the team did not claim comparison with other current entries.

PaceBack's design rationale instead cites [Rhea's 2025 concussion-app usability study](https://formative.jmir.org/2025/1/e67275) for easy navigation, clear voice/report states, reduced interaction time, error recovery, and visual/cognitive-load concerns; the [2019 pediatric NeuroCare study](https://humanfactors.jmir.org/2019/2/e12135) for user-centered iteration, mean SUS 81.9, greater than 90% success on 11 of 12 tasks, and concern about reading/screen-time burden; and a [2025 adult app study](https://humanfactors.jmir.org/2025/1/e75323) for three user-and-clinician iterations using MAUQ, MARS, interviews, and safety assessment. These sources informed the implementation but are not evidence that PaceBack itself is usable, accessible, safe, or effective. PaceBack has not yet run representative-user testing, SUS, MAUQ, or MARS.

## Evidence packet for judges

1. Public source repository and exact commit.
2. Four-minute video using only synthetic profiles/documents.
3. `make verify` output with test counts and toolchain versions.
4. Benchmark/evidence hashes; matching real-pack/fallback diagnostics showing the automated retrieval difference and latency cost, zero automated age leaks/canary executions, unchanged 40/100 response-type and 3/63 boundary matches, and no human review; plus the four one-variable summaries/comparison only if later completed.
5. Threat model, clinical limitations, privacy design, source provenance, and release blockers.
6. Accessibility checklist and screenshots with no real health data.
7. Current development ZIP, main/helper/model-manifest hashes, strict Apple Development signature evidence, and responsive startup smoke. The full encrypted-helper lifecycle smoke is from the preceding package and must be repeated against the current hashes; Developer ID/notarization/stapling/clean-Mac records remain explicitly absent.
8. Separate iOS evidence: `PaceBackiOS.xcodeproj`, shared `PaceBackiOS` scheme, generic Simulator Release build, 34/34 tests across nine suites, the 157,716,998-byte signed/hashed atomic installation receipt, and one source-linked 361 ms simulator retrieval smoke. State explicitly that iOS has no Python sidecar, generation, training, clinician-plan RAG, calibrated thresholds, physical-device benchmark, accessibility review, archive/signing, or distribution evidence.

Judges should be able to distinguish implemented behavior, automated evidence, reviewed evidence, planned work, and unvalidated claims without relying on narration.
